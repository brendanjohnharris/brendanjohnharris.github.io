# brendanjohnharris.github.io

Source for [brendanjohnharris.github.io](https://brendanjohnharris.github.io), a [Hugo](https://gohugo.io) site with three pages: a landing page, a publication list, and an embedded CV. It uses no theme; every template and the full stylesheet live in this repository.

## Building locally

```sh
git submodule update --init      # CurriculumVitae, for the CV page
hugo server                      # preview at http://localhost:1313
hugo --minify                    # build into ./public
```

CI builds with Hugo 0.167.0 (extended). Without the CurriculumVitae submodule the site still builds, but the CV page has no PDF.

## Layout

```
hugo.toml                    config, nav menu, module mounts, excluded static files
content/                     one _index.md per section (front matter only)
data/
  identity.yaml              name, role, contacts, blurb, research interests
  publications.yaml          generated by scripts/fetch_publications.py; do not edit by hand
  publications_overrides.yaml  per-DOI skip / featured / pdf / image
  colors.yaml                palette, synced from Fathom.jl at build time
  presentations.yaml         unused (section disabled)
  software.yaml              unused (section disabled)
layouts/
  _default/baseof.html       page shell: sidebar + main
  index.html                 landing page; shows featured publications
  publications/list.html
  cv/list.html               embeds /cv/main.pdf
  partials/                  head, sidebar, footer, SVG glyphs
assets/css/
  tokens.css                 Go template; emits colour variables from data/colors.yaml
  site.css                   stylesheet
static/img/                  images; full-size originals are excluded from the build in hugo.toml
scripts/fetch_publications.py
CurriculumVitae/             git submodule; main.pdf is mounted at /cv/main.pdf
```

The `presentations` and `software` sections have layouts and data but are disabled with `build: {render: never}` in their `_index.md`.

## Data sources

**Publications.** `scripts/fetch_publications.py` lists DOIs from ORCID and fills in each entry from Crossref (title, authors, venue, date), taking the citation count as the larger of the OpenAlex and Semantic Scholar counts; entries are sorted newest first by publication date. Code links come from `url = {github.com/...}` fields in `CurriculumVitae/theBibliography.bib`. Everything else is set per DOI in `data/publications_overrides.yaml`:

```yaml
"10.1103/physrevx.14.031021":
  featured: true                    # show on the landing page
  image: img/criticality-480.webp   # landing-page thumbnail
  pdf: https://...                  # adds a pdf tag
  news: https://...                 # adds a news tag
  video: https://...                # adds a video tag
  skip: true                        # drop the entry
```

The script overwrites `data/publications.yaml`, and loses the code links unless the CurriculumVitae submodule is checked out:

```sh
pip install requests pyyaml
python scripts/fetch_publications.py
```

**Palette.** `data/colors.yaml` is a committed copy of [Fathom.jl/test/colors.yaml](https://github.com/brendanjohnharris/Fathom.jl/blob/main/test/colors.yaml); CI fetches the current version before each build. `assets/css/tokens.css` maps named colours to CSS variables for the light and dark schemes, with hard-coded fallbacks for missing keys.

**Images.** Since landing-page thumbnails are displayed at 200 px wide or less, a large source image gets a downsampled copy (`criticality-480.webp` from `criticality.webp`, and likewise for `me` and `spatiotemporal_motifs`). Files listed under `excludeFiles` in `hugo.toml`, such as full-size originals, stay in the repository but are not published.

## Deployment

`.github/workflows/build.yml` builds and deploys to GitHub Pages on every push to `main`, on manual dispatch, and on the `update-cv-submodule` repository dispatch. Each build pulls the latest CV, palette and publication data, and passes the CV's last commit date to the CV page header.

`.github/workflows/update-cv-submodule.yml` runs on the same dispatch, sent by the CurriculumVitae repository, and commits the new submodule pointer.
